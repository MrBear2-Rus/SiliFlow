## 1. 做什么

一款**数字电路原理图编辑器**，形态对标 Logisim Evolution：

- 门级 / 寄存器级原理图为主入口，画完即得一张能看的电路图；
- **画到哪跑到哪**：输入端口点一下就翻转，导线颜色实时反映 0/1/X/Z，时钟能单步也能自动走；
- 选几个引脚就能**跑出一张真值表**并导出；
- 同一份设计能以 **Verilog** 文本查看与编辑，**图 ↔ 码双向同步**；
- 能打开 **VCD 波形**，与原理图导线联动查看。

它不做芯片实现，负责的是「想清楚电路长什么样、并且能当场验证对不对」这一段。

## 2. 不做什么

| 方向 | 决策 |
| --- | --- |
| FPGA 侧（综合 / 布局布线 / 下载 / 时序） | 不做，不留面板 |
| 门级延迟与时序分析 | **求值是零延迟的**：组合用「迭代到不动点」，时序只在时钟沿锁存。不模拟 ns 级传播延时，不做建立 / 保持时间检查，不画时序图 |
| 高速连续仿真与信号录制 | 不做。自动节拍上限 ~20 Hz（够人手看）；要长时间波形请走外置仿真器 + VCD |
| 三态 / 总线强度（weak / strong） | 不做。`Z` 只是四值逻辑的一个取值，不区分驱动强度，多驱动冲突一律判 `X` |
| 子电路（把一块电路包成模块再例化） | 本期不做。`tunnel` 只能做命名网络，不能做层次 |
| Agent（双模智能体 / RPC / Plugin） | 不做 |
| 首个里程碑交付物 | **完整框架骨架**——所有分层都在、接口定死、能跑起来能看见 |

## 3. 必须成立的五件事

1. **能开** — 双击 `SiliFlow.exe` 启动，wxAUI 主窗口、菜单、状态栏、各停靠面板齐全。
2. **能画** — 从元件库拖一个与门到画布，连线、选中、移动、删除、撤销都工作。
3. **能跑** — 点输入端口能看到下游电平实时变色；给时钟能单步、能自动走；能复位。
4. **能算** — 框选一块电路，选好输入输出，一键出真值表，能导出 CSV。
5. **能转 / 能看** — 画好的图导出 `.v`；改动 `.v` 后重新导入不丢元件。打开 `.vcd` 画出跳变沿；点波形信号画布上对应导线高亮。

## 5. 复用策略（SigFlow → SiliFlow）

SigFlow 约 23,000 行 C++，逐模块处置：

| 模块 | 处置 | 要点 |
| --- | --- | --- |
| `CanvasElement`（图元 / 引脚 / 元件） | 改造 | 保留 `std::variant` 图元设计；去掉 `Path` 与仿真指针；`TopModuleBox` / `SecondElement` 合并 |
| `Wire`（导线） | 改造 | 保留控制点 / 端点 / Z 形布线；**删掉推演逻辑**，四值枚举留作着色 |
| `SigTree`（层次网表 + Arena） | 改造 | 保留 Arena 与树结构，剥离 FPGA 工程绑定层 |
| `ToolStateMachine`（工具状态机） | 直接复用 | 7 工具 + 子状态设计成熟，几乎不改 |
| `CanvasPanel` / `CanvasEventHandler` | 改造 | 保留命中测试 / 坐标转换 / 缩放；渲染逻辑拆到独立 `CanvasRenderer` |
| `HandyToolKit`（吸附 / 对齐） | 复用 | — |
| `canvas_elements.json` + 元件库面板 | 复用 | JSON 字段名不动，SigFlow 元件定义可直接搬 |
| `MainFrame.cpp`（4,635 行上帝类） | **重写** | 拆到 `app/`，单文件 ≤ 600 行 |
| `wave/`（波形面板） | 改轻量版 | 去 OpenGL 与懒加载索引，用 `wxGraphicsContext` 直绘 |
| `trace/`（sidecar 索引） | 舍弃 | 本期波形文件规模小 |

| `JobService` / SHA-256 记账 | 保留目录不实现 | 供后续接外部工具 |
| `FpgaSynthesis*` / `debug/` / `Simulation/` / `PluginManager` | 舍弃 | 超范围 |

> 移植的每个文件顶部标注 `// Ported from SigFlow: <原名>`，移植后全局搜 `Fpga` `Simulation` `tree_sitter` 确认无残留。

## 6. 架构：四层

```
L4  app/        MainFrame · MainMenuBar · AppContext
                wxAUI 装配、菜单路由、文件生命周期、事件总线
────────────────────────────────────────────────────────────
L3  canvas/     CanvasPanel · CanvasEventHandler · ToolStateMachine
                CanvasRenderer · CanvasNoteBook
    panels/     ToolboxPanel · PropertyPanel · TreePanel
                WavePanel · ConsolePanel · io/VcdReader
    verilog/    VerilogEmitter · VerilogLexer · VerilogParser
                VerilogLayout · SyncBridge
                把操作翻译成模型变更；把模型渲染成像素；把模型 ↔ 文本互转
────────────────────────────────────────────────────────────
L2  core/       Shape · ComponentDef · ComponentInstance · Wire
                CircuitSheet · Project · Library · UndoStack
                纯数据结构 + 序列化，不 include 任何 wx 控件
────────────────────────────────────────────────────────────
L1  3rd/ + res/ wxWidgets · nlohmann/json · vcd · 资源
```

**四条铁律**

1. 只能向下依赖，禁止反向 include。
2. `core/` 里出现 `wxPanel` / `wxMouseEvent` 即设计错误；允许 `wxPoint` / `wxRect` / `wxColour` / `wxString` 这类值类型。
3. L3 内部模块之间**不横向依赖**（`canvas/` 不 include `panels/`），跨模块走 `AppContext` 事件。
4. 只有 L4 可以同时 include 多个 L3 模块。

## 7. 关键设计要点

### 7.1 数据模型（`core/`）

| 类 | 职责 | 关键点 |
| --- | --- | --- |
| `Shape` | 7 种图元的 `std::variant`：线 / 矩形 / 圆 / 弧 / 贝塞尔 / 多边形 / 文本 | 统一 `Draw` / `Bounds` / `Translate` / `Rotate90` / `MirrorX` / JSON 往返 |
| `ComponentDef` | 元件模板（引脚 + 图元 + 类别 + Verilog 映射字段） | 从 JSON 加载，格式沿用 SigFlow |
| `ComponentInstance` | 模板 + 位置 + 旋转 + 镜像 + 标签 | **单一变换管线**：局部 → 绕中心 → 镜像 → 旋转 90°×q → 平移；旋转前后重算 `pos` 保持中心不动 |
| `Wire` | 控制点序列 + 两端端点 + 四值信号 | Z 形布线（水平-垂直-水平）；用户拖出的拐点在重连时保留 |
| `CircuitSheet` | 一张图纸（元件 + 导线 + 注释 + 命中测试 + 端点吸附） | — |
| `Project` | 多图纸工程，落盘 `.sfproj`（纯文本 JSON，便于 Git diff） | 记录 `linkedVerilogPath` + `lastVerilogSync` 供同步仲裁 |
| `Library` | 元件库：查找 / 分类 / 搜索 / 加载 / 内置构造 | `CreateBuiltin()` 零资源依赖；也可读外部 JSON |
| `UndoStack` | **快照式**命令（非细粒度反向操作），默认 100 步 | 骨架阶段可靠优先，单图 JSON < 200 KB 足够便宜 |

**四值逻辑** `LogicSignal { Zero, One, X, Z }` 现在是**真的在推演**（见 7.6）：仿真引擎算出每个网络的值，导线着色只是它的投影。仿真关闭时仍支持手工指定；VCD 导入的值只影响显示，不参与求值。

> v2.x 时这条写的是「仅用于着色，不做推演」。S1 起撤销该限制。

### 7.2 画布（`canvas/`）

- **三套坐标**：逻辑（1 单位 = 10px，落盘用）/ 画布（px，内部统一）/ 设备（px，鼠标与绘制）。转换只在 `DeviceToCanvas()` / `CanvasToDevice()` 两处实现，别处不得自己算。网格吸附 10px，`Shift` 临时关闭。
- **工具状态机**：7 个主工具 `DRAG / SELECT / TEXT / COMPONENT / WIRE / DRAWING / ERASER`，各自子状态。切工具一律回 `IDLE`，`Esc` 从任意子状态回 `IDLE`，状态变化广播给状态栏。
- **职责切分**：`CanvasPanel` 管窗口 / 滚动 / 缩放 / 重绘调度；`CanvasRenderer` 管画什么、按什么顺序画；`CanvasEventHandler` 管事件语义；`ToolStateMachine` 管状态。
- **绘制顺序**：背景 → 网格 → 导线 → 元件 → 标签 → 注释 → 选中高亮 → 预览层 → 悬停提示。
- **撤销边界**：一次完整手势 = 一个事务（`LeftDown` 取 before，`LeftUp` 取 after）。画布平移 / 缩放**不记入**撤销栈。
- **性能下限**：1000 元件 + 2000 导线时平移缩放流畅。手段：视口裁剪 + `wxGraphicsPath` 缓存。

### 7.4 Verilog 双向同步（`verilog/`）

**图是主体，码是投影**；同步不实时，由两个显式动作驱动：`F7` 导出（图 → 码，覆盖写）、`F8` 导入（码 → 图，图纸级重建）。

**导出（图 → 码）三步**：① 收集 `port` 元件定端口 → ② 导线并查集推导网络（网络名优先取 tunnel 标签 / 端口名 / `n_<序号>`）→ ③ 逐元件按 `gate`/`kind` 映射成 `assign` / `always`。**无映射的元件发射为注释，绝不静默丢弃。**

**导入（码 → 图）**：自写词法器 + 解析器（只吃 Verilog 子集：模块头、`assign`、门实例化、`always @(posedge)` 单语句），再用**分层列式布局**定坐标——建图 → 拓扑分层（有环则 Tarjan 压缩 SCC）→ 层内重心排序 → 落坐标（列距 220 / 行距 90，吸附网格）→ `Wire::Route()` 布线 → 重叠消解。

**为什么不用 tree-sitter**：SigFlow 引它是为语法高亮的精确性与错误恢复；本期只需解析子集，代价不成比例。自写约 650 行，编译时间可忽略，报错还能精确到行。`generate` / `task` / `function` / `case` / 参数化模块等**明确不支持并报行号**。

**冲突仲裁**：图纸 dirty 且 `.v` 的 mtime 晚于 `lastVerilogSync` 即冲突，弹三选一——用图覆盖码 / 用码覆盖图（先提示会丢手工布局）/ 取消。

### 7.5 VCD 波形

- **`VcdReader`**（自写约 300 行）：解析 `$timescale` `$scope` `$var` 与值变化段；其余 `$xxx` 段落一律跳到 `$end`，保证不崩。
- **`WavePanel`**：左侧按 scope 的信号树（带过滤框），右侧波形区——1 位画电平跳变（X / Z 用灰 / 蓝填充），多位画数值块（变化处置斜纹）；顶部时间轴 + 可拖游标。
- **联动**：波形点信号 → 按网络名反查导线 → 高亮 + 画布滚动定位；画布点导线 → 波形滚动并高亮同名信号。名匹配规则：去掉位选（`dout[3:0]` → `dout`）后精确比较，大小写不敏感。
- **不做**：波形比较、模式搜索、OpenGL 渲染、sidecar 索引与大文件懒加载。

### 7.6 实时仿真与真值表（`core/sim/`）

**目标形态**：对标 Logisim —— 改一处电路立刻看到电平；点输入端口翻转；时钟能单步也能自动走；选引脚能跑出一张真值表。

#### 求值模型：两层，都不带延迟

- **组合层**：输入变 → 重新求值 → 传播到下游，**迭代到不动点**。设迭代上限（默认 100），超限判「组合环振荡」，把参与的网络全标 `X` 并在状态栏提示。
- **时序层**：只推进全局 `tick` 计数。一次 tick 固定五步 —— ① 时钟置高 ② 组合传播到不动点 ③ 时序元件采样输入、更新状态 ④ 时钟置低 ⑤ 再传播到不动点。**顺序不能换**，换了 `dff` 级联的行为就不对。
- **多驱动冲突**：一个网络被多个输出引脚驱动且值不一致 → 该网络标 `X` 并提示。不做强度仲裁。

**求值图**直接复用 `CircuitSheet::BuildNets()` 的并查集结果（网络 = 等电位点），求值只在「元件引脚 ↔ 网络」之间跑，不另建图。**全量重建**，不做增量；1000 元件规模毫秒级，真成瓶颈再加脏区域传播。

**元件行为**是一张按 `gate` / `kind` 的分派表，**不为每个元件写类**——`Library::CreateBuiltin()` 已经把标签打好了：

| 标签 | 行为 |
| --- | --- |
| `gate`（and/or/not/nand/nor/xor/xnor/buf，含 3 入变体） | 四值真值表逐位算 |
| `kind = const` / `port` / `clock` / `dff` / `mux2` / `add` / `splitter` / `tunnel` | 常量驱动、可翻转输入、时钟相位、沿锁存、`sel ? b : a`、全加器、位选透传、网络别名 |
| `kind = led` | 不驱动网络，只按输入值着色 |
| 无标签 | 视为**不驱动**（输出悬空 = `Z`），并记一条消息；绝不静默当成 `0` |

#### 仿真状态放哪（硬约束）

**运行时的值全部放独立的 `SimState`，按 `compId` / 网络名索引，绝不写回 `ComponentInstance` 或 `Wire`。**
撤销栈是「图纸级 JSON 快照」，仿真值一旦进图纸数据，用户每点一次输入端口都会压一张快照，撤销就变成「往回撤电平」这种荒唐行为。

`Wire::signal` 随之收紧：仿真关闭时 = 用户手填（沿用现在的行为）；仿真开启时 = **只读**显示值，属性面板里置灰。要手动 preset 电平，走「**强制电平**」开关（Logisim 的 Pin 概念），强制时该点作为驱动源参与求值。

#### 与 UI 的接入

- 新菜单「**仿真**」：运行 / 停止、单步（`Ctrl+T`，对齐 Logisim）、复位（`Ctrl+R`）、自动节拍开关与频率、生成真值表…
- 新面板：**真值表**（可停靠，与波形 / 消息同排）。属性面板加一组「仿真」（当前值 / 强制电平 / 时钟频率）。
- 导线着色改为「**仿真值优先**，无仿真结果时退回 `wire->signal`」——`CanvasRenderer` 的着色代码不用重写，只换值的来源。
- 画布交互：`SELECT` 工具下**单击（没拖动）命中 `input` 端口就翻转电平**，不进入移动；拖动仍然是移动。**只认输入端口** —— 常量、指示灯、输出端口都不该被点着翻转。这是 Logisim 的核心手感，不能省。
- 自动节拍用 `wxTimer`，**由 `MainFrame` 持有**（不进 `core/`、不进 `Services`），1~20 Hz，默认 2 Hz。

#### 真值表

本质是「锁住输入端口 → 穷举 2ⁿ 组合 → 每组跑一次组合求值」，**复用同一个引擎**，不写第二个求解器。

- 界面：表格式面板，行 = 一个输入组合，列 = 选中的输入 + 输出端口；列头可点，在「输入 / 输出 / 忽略」之间切换。
- 输入来源只认电路里已有的 `port` 元件（和 Logisim 一样，不凭空加引脚）；没有就提示用户先放。
- 上限：输入数 ≤ 12（4096 行），超了拒绝并提示。
- **必须用独立副本**：穷举要反复写输入、跑传播，绝不能动用户屏幕上那份 `SimState`，否则生成完真值表电路就被搅乱了。
- 含 `dff` / `clock` 时警告「结果取决于初态」，仍允许出表（Logisim 直接拒绝，我们给出信息但不拦）。
- 输出含 `X` 的行原样显示 `X`，不做猜测——真值表一半的价值就在于暴露 `X`。
- 导出 CSV（UTF-8）。

#### 综合（真值表 → 电路）

**本期不做**，只留位置。要做就走这条路：真值表 → 最小化 SOP/POS → **生成 Verilog** → 复用 7.4 的「码 → 图」导入器落到画布。这样不写第二套布局器，还能顺带把 M4 做出来。

#### S1 落地时对已有代码做的两处修正

1. **`ground` 的引脚从输入改成输出**（`Library::CreateBuiltin`）。接地是常量 0 驱动源，原来标成 `PinDir::Input` 会被仿真当成负载，网络就没有驱动了。绘制位置没变。
2. **`Wire::DrawStyled` 增加一个「外部指定电平」的重载**。渲染器要用仿真值着色，但不能为了高亮去改模型 —— 所以电平作为参数传进去，而不是写回 `Wire::signal`。

### 仿真线（S 系列，v3.0 新增）

| # | 内容 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| **S1** | 组合实时仿真 | `core/sim/` 引擎 + `gate`/`const`/`port`/`led` 求值 + 导线实时着色 + 单击翻转输入 + 复位。放一个与门 + 两个输入端口 + 一个 LED：点输入能立刻看到 LED 变色，`X` 情况显示正确 | ✅ 已完成 |
| **S2** | 时序 tick | `clock` / `dff` / `mux2` / `add` 求值 + 单步 + 自动节拍 + 复位。`clock → dff → dff` 接成 2 位移位寄存器，单步 4 拍看到数据右移，复位后归零 | ⏳ 待开始 |
| **S3** | 真值表 | 真值表面板 + 穷举 + 导出 CSV。全加器（3 输入 2 输出）8 行真值表正确；输入数超 12 给出拒绝提示 | ⏳ 待开始 |
| **S4** | 真值表 → 电路（综合） | **本期不做**，位置见 7.6 末尾。要做时走「真值表 → Verilog → 复用 M4 导入」 | ⏸ 搁置 |

**为什么 S 优先于 M3 / M4**：仿真是「画了能立刻验证」的闭环，缺了它整个工具只能画不能验，价值打折；Verilog 同步属于锦上添花。另外 S1 建立的「按网络读写值」这套能力，M4 导入时正好复用。

**M5（VCD）与仿真的关系**：两者共用同一套四值语义和着色，但**不共用代码路径**——VCD 是离线读文件回放，仿真是在线求值。M5 只在「颜色约定」上跟 S1 对齐。

## 11. 主要风险

| # | 风险 | 应对 |
| --- | --- | --- |
| R1 | 图元旋转数学易在弧 / 贝塞尔上出错 | 单独单测：7 种图元 × 4 象限 × 镜像 |
| R2 | 总线（`a[3:0]`）语义未定 | 本期只支持 1 位链路，多位走「端口位选 + splitter 图标」简化方案，标为扩展点 |
| R3 | 导入重建后元件 `id` 全变，撤销栈失效 | 导入前压一张完整快照，一次撤销回到导入前 |
| R4 | 自动布局不满足手工审美 | 布局独立成 `VerilogLayout`，提供紧凑 / 宽松两档；手工拖过的坐标不被下次导出覆盖 |
| R5 | 大图性能 | 视口裁剪 + `wxGraphicsPath` 缓存 + 网格分档；缩放 < 0.4 只画包围盒 |
| R6 | 移植代码带进 FPGA / 仿真残留 | 顶部标注来源 + 全局搜关键词确认 |
| R7 | VCD 超大文件 | 本期设 100MB 上限，超限拒绝加载 |
| R8 | **组合环导致死循环** | 单次传播设迭代上限（默认 100），超限把环上网络全标 `X` + 状态栏提示。这是必须做的防护，不是优化 |
| R9 | **仿真值污染图纸数据，撤销栈炸掉** | 硬约束：运行时的值只进 `SimState`，一个字节都不写回 `ComponentInstance` / `Wire`。见 7.6 |
| R10 | 真值表穷举爆炸 | 输入数上限 12（4096 行），超限直接拒绝并提示 |
| R11 | 求值图全量重建的性能 | 先接受（1000 元件毫秒级）；真成瓶颈再上脏区域增量传播，接口留好口子 |
| R12 | 四值语义偏差（多驱动 / 悬空 / `X` 传播） | 不引入强度仲裁：多驱动冲突与悬空一律判 `X`，并把原因报到状态栏。宁可保守报 `X`，也不猜 |
| R13 | 用户不知道真值表要先放 `input`/`output` 端口 | 生成前校验并给出明确提示，附带「一键放置缺失端口」的引导 |
